# 下一步路线

当前基线为 0.2.1。下列内容均为后续方向，不代表已经实现或验证，也不承诺具体版本号与发布日期。优先完成兼容性和准确性验证，不先扩充界面数量。

## 1. 真实站点兼容性验证

**目标**：确认 linux.do 与 meta.discourse.org 上的核心操作和数据边界。

- 检查页面初始化、主题内跳楼、切换主题、离开主题后的清理。
- 检查深浅色、编辑器避让、窄屏、小窗与键盘操作。
- 检查主动加载、取消、权限错误、限流和人机验证提示。
- 记录测试日期、浏览器、脚本管理器、站点主题及可确认的 Discourse 版本；没有测试过的组合不标为支持保证。

**完成条件**：核心场景逐项记录结果；打开面板无额外数据请求，主动加载仅使用同源只读接口。无法通过验证时停下并保留失败记录，不绕过站点验证。

## 2. 接龙判断与读音校准

**目标**：减少断链、分叉和多音字误判，同时保留可解释性。

- 用经授权的样本检查回看窗口、平台回复优先级与回溯搜索边界。
- 补充多音字、非规范词组、混排文本、缺失前文与手动纠正的反例。
- 将可复现问题改写为虚构或脱敏的测试数据，而不是把真实用户名、正文整帖放入仓库。

**完成条件**：参数或读音变更有独立测试样本支持，明确记录误判与漏判；不能只靠调过参数的同一组样本宣称准确率提升。

## 3. 重复问答归组校准

**目标**：区分同一问题的不同说法，以及措辞相近但含义不同的问题。

- 建立经授权、人工标注的中文长帖样本，并分开用于调参与验证。
- 检查漏分、误分，以及明确回复和引用关联出的回答是否便于用户核对。
- 持续标明字面匹配和已载入范围，不把相似度当作答案正确性的证明。

**完成条件**：归组策略变化有可复现对照，同时报告误分与漏分，不仅展示成功案例。

## 4. 大帖与操作回归

**目标**：在补齐上下文和长时间阅读时保持可操作、可取消、状态不丢失。

- 继续覆盖长链、高分叉、大量无法承接、问答密集及数据缺口场景。
- 检查加载期间的滚动响应、取消后的数据保留、重复操作和存储失败提示。
- 保留现有性能、键盘与窄屏回归；测试环境和测量方法需要一并记录。

**完成条件**：现有回归持续通过，新增瓶颈有有界的复现样本与测量结果。不能用单一合成基准承诺任意规模实站表现。

## 当前不纳入路线

- 自动发帖、点赞、自动接龙或代替用户操作论坛。
- 上传原帖到第三方模型、云端生成答案或跨帖汇总个人信息。
- 无限制后台抓取、自动重试或绕过站点限流与人机验证。
- 未经验证就扩展到任意 Discourse 站点、恢复复杂关系地图或承诺“智能理解全帖”。

这些是当前范围取舍。未来若确有需求，应先说明收益、权限、隐私和成本变化，再决定是否调整。
