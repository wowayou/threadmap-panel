# 项目暂停与重启条件

## 当前决定：暂停，不继续投入

用户决定本轮到此为止：不继续开发、不启动新的实站验证、不发布当前新版或扩大试用；保留现有代码、测试、产物与记录，不删除成果，也不执行远端仓库归档。后续用户明确授权将现有成果与暂停记录提交、推送至 `origin/fix/v0.2.2-security-compat` 以同步进度；这不代表恢复开发、合并主分支或发布 Release。被忽略的 `dist/` 与 `acceptance/artifacts/` 仍只保留在本地，不随源码推送。

暂停的主要原因是产品收益尚未得到验证，而不只是还有技术缺陷：接龙场景较窄，长帖问答的字面归组与明确回复/引用关系只能帮助找线索，不能判断回复是否正确、适用于当前问题或已经过时。继续增加界面、缓存或加载功能，并不能直接解决这个价值缺口。此判断是当前投入决策，不是经过独立样本评估后证明工具完全无用；如果目标只是更快找到可核对的原帖，仍可能有价值，但目前没有足够证据支持继续。

暂停基线：未发布构建 `0.2.1 · 727b2fe4348a`；R7 已本地复验，历史结果为 403/403 测试、81/81 浏览器场景通过。实站原标签刷新 N1、站点兼容性与读取许可仍未完成验证。详见[进度与复验记录](acceptance/progress-review-2026-10-19.md)。暂停不等于发布验收通过，本次同步也不重新运行上述测试。

## 重启前必须回答的问题

下次提出继续时，先回答以下问题，再决定是否重启；“已经做了很多”不作为继续投入的理由。

1. **谁在什么场景下反复遇到什么困难？** 提供少量允许使用的真实例子、发生频率和当前处理方式；避免只有“长帖可能需要”的假设。
2. **与现有办法相比，究竟省了什么？** 对比论坛搜索、浏览器查找、回复/引用跳转及人工阅读，指出本工具能减少的时间或漏找，是否值得安装与维护。
3. **要找相关回复，还是要给出准确答案？** 若接受线索工具，明确用户仍需核对原帖；若必须回答正确，说明如何处理无答案、冲突、过时和条件不一致。不能把关联到回复或点赞数当成正确性的证明，也不默认加模型就能解决。
4. **如何证明效果值得继续？** 约定经授权、独立于调参的样本、对照方法和通过门槛，覆盖误归组、漏找、关联无关回复与没有可靠答案；同时衡量找答案的耗时。先确定门槛，不凭演示成功或自动化测试数量判断产品价值。
5. **最小范围与投入上限是什么？** 优先只选一个有证据的场景（接龙或问答），约定时间/维护上限与停止条件。是否需要补取、正文缓存或模型另行论证；涉及站点读取、外发或付费时，先明确许可、隐私边界及费用/请求上限。
6. **什么新证据足以改变本次暂停决定？** 明确本轮要检验的假设、谁来试、何时复盘；没有可验证收益或达到投入上限仍不达标，就继续暂停，不靠扩功能延长项目。

建议下次直接填写：

```text
目标用户与具体场景：
真实例子、使用许可与发生频率：
现有办法及其不足：
要提供的结果（相关回复线索 / 准确答案）与可接受边界：
最小功能范围：
验证样本、对照方式与通过门槛：
时间/费用上限与停止条件：
改变暂停决定的新证据：
```

**重启顺序**：先确认价值假设和有界验证方案，再由用户明确决定是否恢复实施。若恢复，重新核对代码、构建、依赖及站点当前规则，不把历史本地通过当作当前保证；在发布或扩大试用前，仍须处理 N1 并完成适用的实站与安全验收。旧路线不自动全部恢复。

## 暂存技术路线（未排期、不执行）

公开基线为 0.2.1；当前未发布工作区已实现本地缓存、空白优先布局、有界按次加载、问题/回复阅读与简体中文/英文界面。取舍见 [本轮方案](plans/discourse-reader.md)，历史本地结果见 [验收与整体评估](acceptance/discourse-reader-2026-10-16.md)；上轮安全/性能审计的原反例已有正式回归；[2026-10-19 修复记录](acceptance/progress-review-2026-10-19.md)又补齐缓存启动撤销遗漏 R7，本地复验通过。原标签刷新 N1 仍待实站核验，暂不扩大试用。以下保留暂停前的候选方向与技术优先级；只有重启后重新确认范围才可能执行，不代表已验证，也不承诺版本号或发布日期。

## 1. 真实站点兼容性验证

**目标**：确认 linux.do 与 meta.discourse.org 上的核心操作和数据边界。

- 先核对站点当前读取规则与账号限制，只按授权的小样本人工操作，不自动抓整帖；本地请求预算不能当作站点许可。
- 检查页面初始化、主题内定位、原帖新标签阅读、切换主题、离开主题后的清理。
- 检查深浅色、编辑器避让、窄屏、小窗与键盘操作。
- 检查确认前零请求、有界加载、跨页互斥/持久冷却、取消/超时、权限错误、限流与人机验证；确认无锁或存储失败时主动加载被禁用。
- 核对真实正文、进度轴、侧栏和编辑器的 DOM/尺寸：只有同时不重叠才是并排，空间不足时明确抽屉。检查缩放、移动端、换语言与布局变化后的焦点；规则页构建标识应与安装脚本一致。
- 对缓存核对账号识别、退出/换号、无可读正文、站点权限撤销和后台冻结边界；不要为验证抓取大批真实私密内容。当前来源提示不能当成逐楼权限认证。
- 403 归因：在新版关闭主动补取时本脚本不发数据请求。若仍有 403，用浏览器网络面板记录脱敏的路径、时间、状态和响应提示（不含 Cookie、令牌或正文）对照判断；不为归因反复请求或切换 IP。
- 记录测试日期、浏览器、脚本管理器、站点主题及可确认的 Discourse 版本；没有测试过的组合不标为支持保证。

**完成条件**：核心场景逐项记录结果；打开面板无额外数据请求，主动加载仅使用同源只读接口。无法通过验证时停下并保留失败记录，不绕过站点验证。

## 2. 接龙判断与读音校准

**目标**：减少断链、分叉和多音字误判，同时保留可解释性。

- 用经授权的样本检查回看窗口、平台回复优先级与回溯搜索边界。
- 补充多音字、非规范词组、混排文本、缺失前文与手动纠正的反例。
- 将可复现问题改写为虚构或脱敏的测试数据，而不是把真实用户名、正文整帖放入仓库。

**完成条件**：参数或读音变更有独立测试样本支持，明确记录误判与漏判；不能只靠调过参数的同一组样本宣称准确率提升。

## 3. 重复问答归组校准

**目标**：区分同一问题的不同说法，以及措辞相近但含义不同的问题。

- 建立经授权、人工标注的中文与英文长帖样本，并分开用于调参与验证；本轮去除英文常见虚词只覆盖已测反例，不能代替准确率评估。
- 检查漏分、误分，以及明确回复和引用关联出的回答是否便于用户核对。
- 持续标明字面匹配和已载入范围，不把相似度当作答案正确性的证明。
- **大语言模型（LLM）只作后续可选评估**：先用独立标注样本测量本地字面算法的漏分/误分；只有收益明确时，再评估由用户主动启用的语义重排/合并建议。事前必须确定供应商或本地模型、实际费用/配额、外发范围与脱敏、输入输出上限、并发/取消/失败策略和提示注入防护；模型结论不得覆盖回复/引用等结构证据，不得触发更多抓帖或论坛写操作。

**完成条件**：归组策略变化有可复现对照，同时报告误分与漏分，不仅展示成功案例。

## 4. 大帖与操作回归

**目标**：在补齐上下文和长时间阅读时保持可操作、可取消、状态不丢失。

- 继续覆盖长链、高分叉、大量无法承接、问答密集及数据缺口场景；保留本轮新增的查询/预览/焦点/冷却反例。
- 已在本地短帖夹具实际恢复 5,000 / 10,000 楼，并记录解析/分析耗时、长任务及一次 Chromium 堆观测；继续补复杂正文、问答密集与有限长会话，检查峰值而非只看单次堆大小。不能将“已知 3,000 ID、只显示 20 楼”的滚动测试当成全帖性能。
- 用有限次数的主题往返、正文编辑、删除/空观察与大响应样本，检查缓存释放、旧 stream、稳定预览 ID 和峰值内存；网络响应已有 16 MiB 上限、所有入口共用 stream 条目上限，但整个会话没有总字节预算。是否需要增量计算、列表裁剪或同步解析切片，须先有测量与收益/兼容性对照。
- 检查加载期间的滚动、取消后保留、两种后台选择与跨刷新冷却。可选正文缓存已实现（默认关闭、24 小时、容量/账号约束、清空）；继续检查断电/浏览器冻结/权限变化，不能用自动重新抓取补偿失败。
- 保留现有性能、键盘与窄屏回归；如加入更多自动化，先评估频率、并发、运行器、存储和维护成本，优先手动本地任务。

**完成条件**：原有预算不放宽，新增瓶颈有独立复现样本和修改前后对照，报告耗时/内存、未覆盖规模与实际停止条件。状态/存储异常须可见且不触发额外请求；没有瓶颈或收益不足则保留当前实现。不能用单一合成基准承诺任意规模实站表现。

## 5. agent 接入的进入条件

[内部只读接口 v1](reader-api.md) 已预留并测试：范围、问答检索、结构证据、显式指定正文，包含输出上限、快照失效与取消；未连接运行脚本、全局对象或外部服务。

先确认实际客户端需要什么，不把“预留接口”扩展为插件市场、自动化发帖或默认外发。连接前必须确定调用方身份、按次授权与撤销、正文/个人信息范围、供应商实际费用/配额和资源上限、提示注入/输出校验、超时/失败策略。返回资料中的指令不产生权限，模型结论不能替代原帖结构证据。没有明确收益则保留内部模块即可。

## 当前不纳入路线

- 自动发帖、点赞、自动接龙或代替用户操作论坛。
- 上传原帖到第三方模型、云端生成答案或跨帖汇总个人信息。
- 无限制后台抓取、自动重试或绕过站点限流与人机验证。
- 未经验证就扩展到任意 Discourse 站点、恢复复杂关系地图或承诺“智能理解全帖”。

这些是当前范围取舍。未来若确有需求，应先说明收益、权限、隐私和成本变化，再决定是否调整。
