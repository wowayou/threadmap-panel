# 可选的刷新恢复：本地正文缓存

状态：本地实施与验收完成，见 [本轮记录](../acceptance/discourse-reader-2026-10-16.md)。接续 [实测反馈验收](../acceptance/field-feedback-2026-10-15.md)。用户已同意在浏览器本地保存帖子正文；保留原有未提交工作，不提交、发布或访问真实论坛。

## 已复验的基线

- 上轮 72 个实现/测试/配置文件的清单逐项校验一致；原 userscript SHA-256 与验收记录一致。
- 重新运行类型检查、构建、271 项测试与 50 项本地浏览器场景，全部通过。
- 不将复验解释为实站通过或 403 归因成立。

## 目标与边界

1. 默认关闭，用户在“规则”页明确开启后，持久化已经合法读到的楼层；刷新时从本地恢复，不触发抓帖、自动滚动或自动续跑。
2. 只保存分析所需的正文 HTML、作者名、时间、楼层/帖子 ID、明确回复与点赞元数据；恢复时重新经过输入校验及惰性文本提取。HTML 不进入活动文档。不存 Cookie、令牌、未发送输入、查询或浏览器滚动位置。
3. IndexedDB（浏览器本地数据库）异步保存，独立于设置与请求冷却。每站最多 3 个主题、总预算 16 MiB；每主题最多 10,000 楼、预算 8 MiB（保守估算，不是浏览器物理磁盘占用），超限淘汰较旧数据并提示。
4. 每楼最多保留 24 小时。恢复/读取缓存不刷新时间；到期不再使用，在脚本运行时清理。浏览器关闭时无法保证定时物理删除。
5. 读取 Discourse 当前用户 ID，未知账号时不使用缓存；匿名或已确认的账号状态发生变化（包括无法再确认）时关闭并清理。缓存按同源、账号、主题验证；只有当前页面已有可读楼层才恢复。可用的新 stream 排除已不在主题里的旧缓存；实时楼层优先，包括空正文，不能用缓存补回删除内容。
6. “关闭并清空”删除当前站点的正文缓存，不删设置、纠正或请求冷却。跨标签页通知停止缓存；每次写入还需在同一事务内核对许可代次，防止迟到写入使清除失效。
7. 只保证恢复已完成写入且未过期/淘汰的数据。缓存失败可见，内存分析继续；不能用自动重抓补偿。面板输入、查询、预览与选中项仍保持原来的页面内存生命周期。

## 隐私与失败边界

- 这是方便阅读的明文本地副本，不是加密保险箱。同源脚本、扩展、共用浏览器的人和浏览器资料备份可能取得副本；账号隔离是避免误展示，不是防御同页恶意脚本的权限边界。
- 同一账号的权限或帖子内容变化无法离线全面验证。未再次观察到的楼层可能过时；界面必须标明缓存来源。退出/换号检测依赖宿主数据，脚本不运行时不能清除残留。
- 容量不足、存储禁用、数据库升级阻塞/损坏、账号未知及事务中断均不得假称保存成功。不会添加依赖、云服务、特权接口或持续后台任务。
- 验收使用已有 Node、Chromium 与本地模拟/拦截网络，手动运行，不增加付费服务或 CI 自动化。

## 验收

- 默认零正文写入；显式开启后刷新恢复更多楼层，恢复过程零请求；回复/真实引用分析保持一致。
- 不恢复未授权账号、错误主题/站点、无可读正文、过期/未来时间、损坏/超限记录；新鲜正文和空正文优先。
- 超额淘汰、配额失败、存储不可用、关闭后刷新、清空与在途写入竞态、跨标签页关闭、换号/退出与主题销毁均有覆盖。
- 不破坏原有请求许可、跨页冷却、模式隔离、预览、焦点、安全扫描与性能预算；类型、构建、全量测试和浏览器验收重跑。
- 收尾检查实际 diff 和文档链接，记录真实构建标识、检查结果及尚未验证的环境。
