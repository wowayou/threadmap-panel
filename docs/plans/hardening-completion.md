# 当前加固改动的实施与验收方案

状态：**本轮本地收尾已完成，未发布**。2026-10-15 终验通过类型、构建、240 项单元/契约/性能测试及 46 项本地浏览器场景，见 [收尾验收记录](../acceptance/hardening-completion-2026-10-15.md)。保留原有工作，新增反例先复现再修复；只完成已授权的加固、有界加载和本地阅读流程。[实施前基线](../acceptance/hardening-baseline-2026-10-15.md) 保留为历史记录，真实站点/旧浏览器仍未验收；截图中追加要求见第 10 节。

## 1. 目标与边界

把 0.2.1 工作区中尚未完成的输入校验、原帖标注隔离、浏览器兼容改写和测试工具链调整收尾，做到：

1. 页面内存数据（store）、页面文档树（DOM，Document Object Model）与接口返回的帖子，经过同一信任边界后才能进入会话。
2. 脚本只识别、修改和清理自己的标注；同名类、错误令牌不能导致用户正文被忽略。
3. 主动加载不接受串帖或未请求的数据，不以“请求了多少 ID”冒充“取得了多少帖子”，不向其他来源跟随重定向。
4. 异常和超限输入不会破坏其他合法楼层，也不会被静默截断后冒充完整帖子参与判断。
5. 现有接龙、问答、只读、安全、性能和界面回归不退步。

保留 [安全基线](../security.md)、[界面基准](../ui-spec.md) 和 [实现说明](../implementation-brief.md) 的只读、会话与可解释性保证。按后续用户要求，原 500ms/整帖加载方案由有界策略替代：每次确认后最多 5 次请求（含主题信息），每批最多 20 个数据库 ID，请求启动间隔至少 5 秒；具体冷却与跨页协调见第 10 节。不自动重试；取消/失败保留已取得的数据；`undefined` 回复信息不等于明确的 `null`；同主题定位不重置会话。

**不在范围内**：规则阈值/词典调优、问答算法升级、界面重设计、新站点适配、云服务、持续集成或定时任务、自动抓取实站、版本发布。真实站点和旧 Safari 的支持保证仍需另外取得实际验证证据。

## 3. A：输入边界与有界正文

### 3.1 解析契约

以 `parsePost(raw, context): Post | null` 为外部帖子入口；`normalizePost` 继续作为内部规范化工具，不把它当外部输入校验器。

- `context` 由调用方提供当前主题和来源，不能被帖子里的 `origin` 等字段覆盖。
- `id` 与 `post_number` 必须是正安全整数，不互相代替。接口/store 帖子字段不使用 `Number(value)` 把布尔值、任意字符串转换成 ID。
- DOM 属性本来是字符串，应在宿主适配层明确解析合法十进制 ID，再交给核心；不可把 `article#post_1` 这种楼层标记猜成数据库 ID。
- 给出 `topic_id` 时必须与当前主题一致；未给出时只在已确认主题的上下文中接受。分批请求必须传本批允许的 ID 集合。
- 回复字段区分未提供、`null`、合法正整数；无效类型/数值不转换成 `null`。
- 正文缺失或 `null` 可按现有空观测语义处理，但不据此宣称“已删除”；正文是非字符串则拒绝。用户名空值、非法时间、非法点赞数使用明确的缺省策略，不影响身份合法的其他楼层。
- 单条异常返回 `null`，不让异常访问器或坏条目使整批合法帖子丢失。容器结构错误由宿主回退或加载器报错处理，不能用大范围 `catch` 把接口错误变成成功的空结果。

### 3.2 上限策略：拒绝超限，而非静默截断

**推荐且作为本轮默认方案**：保留当前拟定的 HTML 200,000、输出文本 20,000、访问节点 50,000 上限，但统一检查位置与超限语义。字符串长度单位是 JavaScript 的 UTF-16 代码单元，不是字节或汉字数。这是本项目的处理策略，不是所有 Discourse 部署的正文上限。

- 在任何 `DOMParser` 调用前检查 HTML 大小；不能解析完整超大输入后才截取输出。
- 有界提取应能向 `parsePost` 区分“完整处理”和“达到工作上限”。超限帖子不进入分析，返回 `null`；加载器据此保留缺口并明确提示数据不完整，不自动重试。
- 不把截断结果作为普通 `Post` 返回：接龙依赖帖内最后一个词，静默截断会改变链头。若要改成“部分帖子”模型，须先提交贯穿类型、判断与界面提示的独立方案，不在这里暗加兜底。
- `htmlToText` 如仍保留给内部调用的字符串接口，也必须有界；外部入口不能因该接口丢失超限信息而误收帖子。优先共用一个提取实现，不复制两套遍历逻辑。
- DOM 与无 DOMParser 分支应用同样的输入/输出边界。节点遍历使用迭代方式，不能无界收集子节点、拼接一个超大文本节点后才裁剪。
- 保留引用、代码、链接预览、投票等排除规则与块级边界；不要在核心按 `.threadmap-badge` 类名删内容。
- 明确上限恰好满足与超过上限的差别，避免把完整的临界输入误判超限。原始 HTML 和文本的保留都应有界。

## 4. B：宿主接线与标注归属

### 4.1 读取 store / DOM

- 两条路径均接入 A；删除绕过解析的直接外部 `normalizePost` 调用。
- `readStore` 校验主题/容器结构；没有 stream 仍表示未知，不能随意改成已知空数组。stream 的 ID 过滤并稳定去重，保留平台顺序。
- 单个 `null`、原始值或坏帖子只丢弃该项。内部模块不可用、容器异常或 `toArray()` 失败时，仍允许原有 DOM 回退。
- store 未给出回复字段时保留 `undefined`；通过会话合并的回归测试，证明不会覆盖此前接口取得的明确回复事实。
- `readDom` 的无效 `data-time` / `datetime` 只影响时间字段，不能让整次读取抛出 `RangeError`。无法确定数据库 ID 的楼层跳过，不猜造 ID；若支持另一种 DOM ID 来源，须先给出可靠结构样本。
- 缓存只保存合法解析结果；相同内容、同一上下文重复读取保留对象引用，内容或上下文变化不能复用错误记录。保持切换主题清缓存的现有生命周期。

### 4.2 一处归属判断贯穿整个流程

- `cookedHtml` 只从惰性副本移除 `OWNED` 匹配的节点，不再按类名删除；实际论坛正文不得因此被改写。
- 插入、复用、删除、样式作用范围、MutationObserver 的自身变化判断使用 `owner.ts` 同一契约。
- 真正的自有标注即使类名变化也不进入正文；正文里的同名类、同名属性但错误令牌必须保留，并作为真实内容参与刷新。
- 令牌用于避免误识别，不是抵御页面内恶意脚本的权限边界；同页脚本能读取令牌，不得宣称“页面脚本无法伪造”。
- 更新旧测试的“自有标注”夹具时使用 `markOwned` 或真实 `applyBadges`，同时新增“同名但非自有”反例。保留原来的幂等、点击、清理、混合 DOM 变化覆盖，不删除失败用例了事。
- demo 与实际脚本使用相同归属契约；深浅色样式不能外溢到非自有元素。

## 5. C：加载器的数据与请求闭环

### 5.1 结构、身份与进度

- 显式验证主题 JSON、`post_stream`、stream 和 posts 容器；给出主题 ID 时校验归属。无法解析或结构错误用可读的 `LoadError` 停止，不返回伪成功。
- 只支持现有明确形态：主题响应的 `post_stream`，分批响应的 `post_stream.posts` 或 `posts` 数组。不为未知结构猜测路径。
- stream/known IDs 校验、稳定去重；主题首批帖子的允许集合取有效 stream，后续批次取实际请求 ID 集合。外来主题、未请求 ID、不合法帖子不能进入结果/回调。
- 已明确提供空 stream 与未提供 stream 是不同情况：前者无需请求；主动刷新由调用方明确省略 stream。不要因为空数组而暗中扩大请求范围。
- 总量是唯一 stream ID 数；已载入量是 stream 与“已有合法 ID ∪ 新取得合法 ID”的交集大小。重复 ID 不重复计数，已知但不属于 stream 的 ID 不撑大进度。
- 批次只返回部分请求 ID：先交出合法部分，再停止并报告“数据不完整，已载入内容保留”；不得增加请求重试补齐，不得报满进度。额外无关条目过滤后不计入成功数量。
- 重复合法 ID 只入库一次；同 ID 的身份字段相互冲突时不能以最后一条覆盖作猜测，应保留缺口并报数据异常。
- 主题响应的首批 posts 本来只是 stream 的子集，不能把正常分页误报为缺失批次。

### 5.2 请求、取消与会话

- **在请求选项中阻止自动重定向**，而不是等 `response.url` 跨源后才拒读。最小方案是 `redirect: 'error'`，保留同源绝对 URL 与 GET 校验。
- 这会拒绝同源重定向，属于明确的安全/兼容性取舍；若实站必须重定向，先给证据再设计有界同源跳转，不能恢复默认 `follow`。
- 验收要观察目标是否收到请求，不只 mock 一个跨源 `response.url`。可用本机两端口，或浏览器全部拦截的模拟重定向；不得向真实第三方发请求。
- 开始前已取消不发请求；批间等待可取消并清理监听器；取消、HTTP 错误、挑战页、解析错误和不完整数据均阻止后续批次，不自动重试。
- 合法已取得数据仍通过进度/结束回调交出；`userscript.tsx` 的节流合并和 `finally` 保留保证不能丢失。
- 若在主题响应中已确认完整 stream，后续失败也应保留该已知范围。可为进度回调显式增加 stream 元数据，在宿主中合并；不能仅凭 total 数量虚构 ID。保持 API 来源说明准确。
- 加载中切换/离开主题：旧请求取消，旧结果不能污染新会话或重新插入旧标注。

## 8. 执行命令与通过条件

实现各段时先运行对应测试；最终在同一份冻结差异上按顺序运行，构建失败则停止，不使用旧产物：

```sh
npm run typecheck
npm run build
npm test
npm run acceptance
# 若本机没有 Playwright 默认二进制，仅显式指定已经可用的浏览器：
# THREADMAP_CHROME=/absolute/path/to/chrome npm run acceptance

git diff --check
git status --short
```

若某个测试失败，为调查可以继续跑其他检查，但必须分别记录退出码，不能因为最后一个命令成功就报告整体成功。性能预算不要与另一份全量测试/构建并发争用资源。全量执行后检查实际差异，排除无关清理、凭据、真实帖子、调试代码与生成文件；`dist/`、`acceptance/artifacts/` 保持忽略。

**通过条件**：

- A/B/C/D 的契约与矩阵通过，原有覆盖完整保留，类型、构建、单元/契约、性能、浏览器均通过；不存在未解释的跳过或无效测试发现。
- 不只提交“全绿”计数：附失败/边界场景的断言结果，尤其是串帖、缺返、跨源目标请求数和取消后的数据保留。
- 记录工作树/提交标识、产物校验值、执行命令/退出码、实际工具和浏览器版本，以及仍未验证的实站/旧引擎范围。
- 当前上限和拒绝策略在用户可见说明中准确，未增加隐性网络行为、自动重试或自动化成本。
- 执行 agent 不自行宣布发布就绪；提交差异与证据后按本清单独立复验。若要求包含实站终验，必须等待明确授权与人工场景记录，不能用本地模拟替代。

## 9. 执行约定

保留当前未提交工作，不从干净 HEAD 覆盖。按 A→B/C→D 及第 10 节补齐加固；不调整算法阈值、不放宽性能预算、不自动访问实站或下载浏览器、不发布。可用独立执行 agent 时按文件责任分工；本次续作没有子 agent 工具，采用反例先行、分段修改、冻结差异后全量复验。工具和进度提示不能作为验收通过证据。

## 10. 追加的加载、阅读与边界验收

### 10.1 加载安全

- 默认及每次确认前零请求，包括未知总量和“检查新楼层”；重复操作不能启动第二条加载链。
- `load-policy.ts` 是本地自保预算，**不是站点公布的配额、读取许可或“不封号”保证**。未取得当前站点政策/账号配额证据；不通过本轮测试请求真实站点。
- 同源 Web Locks（浏览器跨标签页锁）互斥，不排队；请求时刻及冷却存入本地存储，刷新、换主题不能重置。无锁、存储异常或时钟倒退则禁止主动加载，不回退到无保护请求。
- 单次最多 5 请求、每批最多 20 ID、启动间隔至少 5 秒、单请求含正文读取超时 20 秒；滚动一小时最多 60 请求。正常结束/取消至少冷却 60 秒，普通错误 10 分钟，401/403/429/验证至少 30 分钟；服务器给出更长的 `Retry-After` 时取更长者，包括 HTML 验证和 503 响应。
- 切后台、页面离开、主题切换会取消；失败、取消、预算耗尽和冷却到期都不自动续跑。关闭/崩溃前预留一小时冷却，不冒充不可绕过的安全边界。

### 10.2 阅读状态与键盘

- 回答使用已载入纯文本预览；多答案游标按稳定帖子 ID，不把答案 ID 替换为问题选中项。不注入原始 HTML，不为预览请求正文。
- 已显示的原帖只在页内定位；未显示时用 `noopener noreferrer` 原生新标签链接，修饰键保持浏览器语义；不调用可能整页刷新的私有路由。
- 查询、当前问题、当前答案、分页及标签滚动位置应在收起/小窗和问答↔规则切换后保留；切主题仍重置。关闭预览恢复入口焦点；入口消失时回到查询框。
- 确认提示须滚入面板可视区域并可键盘操作；Esc 先取消确认并返回加载按钮，不直接收起面板。长文本在 320px 下不横向溢出，预览操作目标至少 24×24。

### 10.3 续作验证与后续边界

| 检查 | 验收证据 |
| --- | --- |
| 验证/503 的较长 Retry-After、请求前时钟倒退 | 正式单元反例先失败再修复；实际加载器与 guard 联测 |
| 预算、间隔、刷新冷却、跨窗口互斥、切后台取消、20 秒超时 | 构建产物 + 全网络拦截；记录请求数、时刻和无自动恢复 |
| 问答切规则/收起状态、预览关闭焦点、确认可见性和 Esc | 组件测试及构建产物浏览器；不能只检查辅助函数 |
| 缺失/空/不再关联的回答、排序变化、长用户名/无空格长文本 | 稳定 ID、明确空状态、纯文本安全及窄屏验证 |
| 性能 | 原 2 万楼接龙 / 1 万楼问答 / 查询预算不变；记录实际测量与大帖滚动长任务。没有瓶颈证据不做缓存/算法重构 |
| 自动化成本 | 仅手动、有限次本机测试；无付费 API、远端 runner、持续服务、定时任务或自动下载；所有模拟外部 URL 拦截 |

需扩大范围的项目放入现有路线图，明确优先级和完成条件：真实站点/脚本管理器和浏览器兼容性优先；更大规模长任务/内存和真实问答准确性另做有界测量。不能以合成测试绿灯承诺任意规模或实站安全。
