# ThreadMap 安全基线

脚本运行在用户已登录的论坛页面里，能看到的东西和用户本人一样多。下面这些约束保护的是安装脚本的人，不是开发便利。由 `tests/security.test.ts` 自动检查；改动任何一条都要先更新本文并说明理由。

## 承诺

| 承诺 | 实现方式 | 检查 |
| --- | --- | --- |
| 只读：不发帖、不点赞、不改论坛数据 | 网络只经过 `src/host/loader.ts`，只有 `GET`；不调用论坛按钮、表单与数据模型写方法 | 源码扫描 |
| 不把帖子内容当代码执行 | 所有文字经 Preact/`textContent` 渲染；HTML 只在 `DOMParser` 生成的惰性文档里解析为纯文本；没有 `innerHTML` 赋值、`eval`、`new Function` | 源码与产物扫描 |
| 不把数据发给第三方 | 请求地址只由数字 ID 拼成，用 `location.origin` 解析为绝对地址并校验同源；被重定向到其他站点时不读取内容 | 单元测试 + 产物外部地址白名单 |
| 不申请特权 | `@grant none`，不用 `GM_*`、`unsafeWindow`，不读写 cookie | 元数据与源码扫描 |
| 不远程加载代码 | 没有 `@require`、`@resource`、`@connect`，产物不含远程脚本；读音数据内置 | 元数据扫描 |
| 作用范围最小 | 只匹配 `linux.do/t/*`、`meta.discourse.org/t/*`，`@noframes` | 元数据扫描 |
| 本地只存两样东西 | `threadmap-prefs-v2`（设置）、`threadmap-overrides-v1`（本地纠正：帖子 ID 与楼层关系），不存帖子正文 | 存储键扫描 |
| 不给论坛制造负担 | 打开面板不发请求；只有点“加载全部楼层”或“检查新楼层”才请求数据，每批最多 20 楼、批间隔 500ms、出错即停、不自动重试 | 加载契约测试 |

## 已知边界

- 读取 Discourse 页面内部数据（`controller:topic`）只做只读查询，任何异常都按不可用处理并退回解析 DOM。页面里的其他脚本理论上能伪造这份数据，最坏结果是显示错误的判断，不会执行代码或发出请求。
- 面板使用开放的 Shadow DOM，页面脚本可以读取其中显示的内容；面板显示的都是页面上本来就公开给该用户的信息。
- 原帖标注是插入正文上方的普通按钮，点击只会打开面板，不会触发论坛行为。

## 分发

- 从仓库 Release 分发未压缩的产物，并附上 SHA-256，方便核对。
- 不使用指向 `main` 分支的自动更新地址，避免仓库被入侵后推送给所有用户；更新由用户手动安装新版本。
- 维护者应开启 GitHub 账号双重验证；发布前运行 `npm run typecheck`、`npm run build`、`npm test`、`npm run acceptance`。先构建再测试，才能检查实际分发产物。

## 报告问题

发现安全问题请先在 Issues 中仅留下私下联系请求，不要公开利用步骤、真实帖子内容或凭据；建立私下沟通渠道后再提供细节。
